# API contract

All endpoints are versioned under `/api/v1`. Successful responses use:

```json
{"success": true, "data": {}, "request_id": "..."}
```

Errors use the same request identifier and never include stack traces,
credentials, raw image bytes, or provider secrets.

## Authentication

User-protected routes use `Authorization: Bearer <access-token>`. Access
tokens are short-lived. Refresh tokens are accepted only by
`POST /api/v1/auth/refresh`, are rotated on use, and are never returned after
the rotation that consumed them.

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/auth/register` | none | Create a user and initial session |
| POST | `/auth/login` | none | Authenticate a user |
| POST | `/auth/refresh` | refresh body | Rotate a refresh token |
| POST | `/auth/logout` | user | Revoke the current session |
| POST | `/auth/logout-all` | user | Revoke all user sessions |
| GET | `/auth/sessions` | user | List the caller's sessions |
| GET | `/users/me` | user | Read the caller's account and profile |
| PATCH | `/users/me/profile` | user | Update the caller's profile |
| POST | `/users/me/password` | user | Change password and revoke sessions |
| DELETE | `/users/me` | user | Delete the account and stored images |

## Analysis and metrics

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/analyses` | user | Upload JPEG/PNG and run the unified pipeline |
| GET | `/analyses` | user | List only the caller's analyses |
| GET | `/analyses/{analysis_id}` | user | Read an owned analysis |
| GET | `/analyses/{analysis_id}/image` | user | Stream an owned private image |
| DELETE | `/analyses/{analysis_id}` | user | Delete an analysis and its image |
| POST | `/metrics` | user | Store a caller-owned health metric |
| GET | `/metrics` | user | List only the caller's metrics |

Uploads are bounded by `MAX_UPLOAD_SIZE_MB`, MIME and decoded-format checks,
minimum quality checks, maximum dimensions, and maximum pixel count. Filenames
are metadata only; storage keys are generated by the server.

## Device contract

### Phone-camera integration

Phone/browser camera scans use `POST /api/v1/analyses` with the user's
`Authorization: Bearer <access-token>`, multipart `image`, and
`source=APP_CAMERA`. No device registration, device secret, or `X-Device-Session`
is required. The success response is `{"success": true, "data": <analysis>,
"request_id": "..."}`; `data` is the analysis itself, not a device-capture wrapper.
Images are owned by the signed-in user. Phone scans share the per-user
`APP_CAPTURE_RATE_LIMIT` (default 3/minute) with legacy app-camera device captures.
The configured `MAX_UPLOAD_SIZE_MB` is enforced before image decoding.

Clients must inspect `error.code` and the HTTP status on failure. In particular,
401 is a user authentication failure, 413 means the image exceeds the size limit,
422 may be `UPLOAD_INVALID` or `IMAGE_RECAPTURE_REQUIRED`, 429 is `RATE_LIMITED`,
and 5xx indicates a service/provider failure. Preserve `request_id` for support
without logging images or credentials. These failures must not all be described
as device authentication errors.

### External hardware

Owner routes use the user bearer token. Device routes use
`X-Device-Session: <session-token>`, except registration and device
authentication:

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/devices/register` | user | Register an owned device; secret returned once |
| GET | `/devices` | user | List owned devices |
| GET | `/devices/{device_id}` | user | Read an owned device |
| DELETE | `/devices/{device_id}` | user | Revoke device and active sessions |
| POST | `/devices/{device_id}/rotate-credential` | user | Rotate secret and revoke sessions |
| POST | `/devices/authenticate` | device ID + device secret | Firmware-friendly session authentication |
| POST | `/devices/{device_id}/authenticate` | device secret | Issue short-lived device session |
| POST | `/devices/{device_id}/heartbeat` | device session | Update heartbeat and software versions |
| GET | `/devices/{device_id}/status` | device session | Read derived device status |
| POST | `/devices/{device_id}/logout` | device session | Revoke the current device session |
| POST | `/devices/{device_id}/capture` | device session | Upload a camera image |
| POST | `/devices/{device_id}/sensor-readings` | device session | Submit VL53L0X distance metadata |

Capture requests require a JPEG in multipart field `image`, the
`X-Device-Session` header, and an `Idempotency-Key`. The optional
`capture_metadata` multipart field is a JSON object with these supported keys:

```json
{
  "image_source": "HARDWARE_CAMERA",
  "camera_type": "ESP32_CAM",
  "firmware_version": "1.0.0",
  "software_version": "1.0.0",
  "capture_timestamp": "2026-01-15T10:30:00Z",
  "sensor_distance_mm": 350
}
```

Image dimensions are decoded by the server; client-supplied dimensions are
ignored. Repeating the same key for the same device returns the original
capture rather than creating another analysis. Capture lifecycle events
(`RECEIVED`, `VALIDATING`, `VALID`, `INVALID`, `PROCESSING`, `COMPLETED`, and
`FAILED`) are stored in the device-capture record and audit log. Device status
is `REGISTERED`, `ONLINE`, `OFFLINE`, `ERROR`, or `REVOKED`; `ONLINE` is derived
from the configured heartbeat timeout. Device and sensor rate limits default
to 10 authentications/minute per client/device, 30 heartbeats/minute per
device, 12 captures/minute per device, and 60 sensor readings/minute per device.

`sensor_type: "distance"` with `unit: "mm"` describes an optional VL53L0X
positioning reading bounded to greater than 0 and at most 2000 mm. It is not a
medical measurement. Production clients must
use HTTPS; the API accepts only JPEG for hardware captures while regular
`APP_CAMERA`/`UPLOAD` analysis requests retain JPEG and PNG support.
Hardware quality checks include decoded dimensions, a basic aspect-ratio
framing sanity check, brightness, and optional calibrated sharpness checking
through `DEVICE_MIN_SHARPNESS`.

## Health and documentation

* `GET /api/v1/health/live` is a process liveness check.
* `GET /api/v1/health/ready` checks database connectivity.
* `GET /api/v1/health` reports the database-backed service status.
* `GET /openapi.json` and `/docs` expose the generated contract. Security
  schemes describe the user bearer token and device session header.

### Photo report observations

New Gemini reports include `result.visual_assessment`: `subject_visible` (boolean),
`framing`, `lighting`, `posture` (plain-language strings), and `capture_tips` (string array).
The field is nullable for older reports and mock mode. Observations describe the uploaded
photo, not measured health. A visible person can produce `OBSERVATION` even when clinical
measurements are unsupported. No person produces `UNAVAILABLE` with recapture guidance.
Gemini confidence is null because this pipeline does not compute a calibrated score;
`UNAVAILABLE` never represents a zero health score. Migration `0004_visual_assessment`
preserves existing reports and persists the new observations.

### Camera angle estimates

`POST /api/v1/analyses` accepts an optional multipart `pose_capture` JSON string
(maximum 16,000 characters). Version 1 uses model
`mediapipe-pose-landmarker-lite-float16-v1`, image `width`/`height`, and status
`DETECTED`, `NO_POSE`, `MULTIPLE_POSES` or `MODEL_UNAVAILABLE`. A detected capture
must contain exactly 33 `{x, y, visibility, presence?}` image-normalized landmarks;
other statuses must have an empty landmark array. Clients cannot submit angles.

The server derives seven angles in pixel coordinates (preserving image aspect
ratio): shoulder-line tilt, hip-line tilt, torso lean, and left/right elbow and
knee angles. Values are degrees rounded to one decimal, with `ESTIMATED` status.
Required landmarks below 0.7 visibility/presence, near/outside image boundaries,
collapsed segments, and dimension mismatches yield null with an explanatory
`UNAVAILABLE` status. Valid zero angles remain zero. These conservative gates
are engineering heuristics, not a validated accuracy guarantee.

`result.camera_metrics` persists in list/detail responses, with method, source,
limitations and individual reasons. Its JSON column is added by migration 0005;
existing reports remain nullable. The data is separate from the Gemini schema:
Gemini cannot author measurements. Valid camera geometry survives a description
provider error, with a warning that the description is unavailable.

These are browser-supplied landmark estimates, not independently attested
server detections, calibrated 3D joint measurements, or medical readings.
Perspective and camera tilt affect them. No height, weight, pulse, age, body
composition or overall health/posture score is inferred from appearance.

### Entered readings and guided reference height (version 1)

`POST /api/v1/analyses` also accepts optional `measurement_inputs` JSON (4,000
characters max). Fields: `version:1`, `age_years` (integer 0–120), `height_cm`
(40–260), `weight_kg` (2–500), `pulse_bpm` (integer 20–250), and optional
`height_reference`. Numeric values must be finite JSON numbers. Unknown fields
and invalid ranges are rejected. These bounds validate input, not clinical normality.

A `height_reference` contains image `width`/`height`, `reference_cm` (20–250),
`same_plane_confirmed:true` and four normalized `{x,y}` points in order: reference
top, reference bottom, head top, foot soles. The server validates same-image
geometry, visible landmarks, upright legs/torso, noncollapsed vertical spans,
reasonable head/feet alignment and supported output height (80–250 cm). It
computes reference_cm * marked_body_pixel_height / reference_pixel_height,
rounded to whole cm. Actual equal depth and known reference size cannot be
verified automatically; the result is labeled a rough, unvalidated reference
estimate with those assumptions. It is not used for BMI.

`result.supplemental_metrics` stores six values with unit, source, status and
reason. Age/height/weight/pulse are `USER_PROVIDED`/`RECORDED`; BMI is `CALCULATED`
only from entered measured height and weight with age 20+; reference height is
`CAMERA_REFERENCE`/`ESTIMATED`. Unavailable readings are null with explicit
instructions. No pediatric BMI classification, body-fat inference, clinical
interpretation or health score is supplied. BMI method:
https://www.cdc.gov/bmi/adult-calculator/

Migration 0006 adds the nullable JSON column; old reports remain unchanged.
Inputs are not passed to Gemini. Saved reports retain the values and source
labels, not the raw reference mark coordinates. Account ownership rules apply.
